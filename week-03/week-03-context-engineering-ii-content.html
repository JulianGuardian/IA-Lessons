    1. The Context Window Problem

    Every model has a maximum number of tokens it can process in a single call — its context window (back from Week 1: input tokens + output tokens together must fit inside this limit). Modern models offer increasingly large windows, but that doesn't make the problem disappear:

    • Cost: you're billed per input token on every single call, including the entire conversation history you resend each turn.
    • Latency: bigger inputs take longer to process.
    • Quality: research on long-context models consistently shows a "lost in the middle" effect — information placed in the middle of a very long context is recalled less reliably than information near the start or end.

    So even when a model can technically hold your whole conversation, you often shouldn't just keep appending to it forever. This week covers three engineering strategies for managing what actually goes into the context window on each call, plus the concept — embeddings — that will let us manage context semantically rather than just chronologically, starting with RAG next week.

    2. Three Strategies for Managing Context

    2.1 Sliding window

    The simplest strategy: keep only the last N turns (or the last T tokens) and drop everything older. Cheap to implement, predictable cost, but older information is permanently lost — fine for a short support chat, risky for anything where early context matters later (e.g. a user stating a constraint in turn 1 that should still apply in turn 20).

    sliding_window.py
    def sliding_window(history: list[dict], max_turns: int = 6) -> list[dict]:
    """Keep only the most recent `max_turns` messages."""
    return history[-max_turns:]

history = [{"role": "user", "content": f"message {i}"} for i in range(10)]
print(sliding_window(history, max_turns=4))

    2.2 Summarization

    Instead of dropping old turns, periodically ask the model to summarize them into a compact block, and keep that summary plus only the most recent turns in full. This preserves information at much lower token cost than keeping full history, at the price of one extra LLM call and the possibility that the summary loses some nuance.

    rolling_summarization.py
    def summarize_history(client, model, history: list[dict]) -> str:
    transcript = "\n".join(f"{m['role']}: {m['content']}" for m in history)
    prompt = (
        "Summarize the key facts, decisions, and open questions from this conversation "
        "in 3-5 bullet points. Be specific, don't generalize away details a follow-up "
        "question might need.\n\n" + transcript
    )
    response = client.models.generate_content(model=model, contents=prompt)
    return response.text

def compact_context(client, model, history, keep_recent=4):
    if len(history) <= keep_recent:
        return history
    older, recent = history[:-keep_recent], history[-keep_recent:]
    summary = summarize_history(client, model, older)
    return [{"role": "system", "content": f"Conversation summary so far:\n{summary}"}] + recent

    2.3 Compression: structured memory

    A more aggressive form of compression extracts only the facts you'll actually need again into a small structured record (a dict, or a schema-forced JSON object from Week 2) — e.g. {"user_name": ..., "preferences": [...], "open_issue": ...} — instead of a paragraph summary. This trades flexibility for even lower token cost and easy programmatic access, and pairs naturally with the persistent session state you'll manage explicitly once we reach Google ADK sessions in Week 7.

    3. Embeddings, Revisited: From Tokens to Whole Passages

    In Week 1 we introduced embeddings as vectors representing token meaning. The same idea scales up: an embedding model can take an entire sentence, paragraph, or document and return a single vector summarizing its meaning. Texts with similar meaning end up with vectors that point in similar directions — which we measure with cosine similarity (1.0 = identical direction/meaning, 0 = unrelated, -1.0 = opposite).

    generating an embedding
    result = client.models.embed_content(
    model="gemini-embedding-001",
    contents="The bike's front brake feels loose.",
)
vector = result.embeddings[0].values
print(len(vector), vector[:5])  # e.g. 3072 dims, [0.0123, -0.0456, ...]
    cosine_similarity.py
    import numpy as np

def cosine_similarity(a, b):
    a, b = np.array(a), np.array(b)
    return float(np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b)))

sim = cosine_similarity(vector_a, vector_b)
print(sim)  # closer to 1.0 = more semantically similar

    3.1 Semantic search, minimal version

    With embeddings and cosine similarity, we can already build a tiny "search engine" with no database at all: embed every candidate text once, embed the query, and rank candidates by similarity to the query. This exact pattern — scaled up with a real vector store and a document-ingestion pipeline — is RAG, which is the entire subject of next week.

    Engineering rule of thumb

    Semantic search finds text with similar meaning, not necessarily matching keywords — a query for "brake problems" can retrieve a passage that says "the caliper wasn't gripping" even with zero shared words. That's the whole point, and also why hybrid (keyword + semantic) search exists, which we'll cover in Week 10.

    5. Key Takeaways & Glossary

    • Context windows are a hard limit with real cost, latency, and quality consequences — not just a memory quirk.
    • Sliding window is cheap and simple but permanently discards old information.
    • Summarization preserves information at lower token cost, at the price of an extra LLM call.
    • Structured memory extraction compresses even further into queryable facts.
    • Embeddings let us compare meaning, not just characters, via cosine similarity.
    • Embeddings + similarity ranking over candidate texts is the minimal seed of what RAG formalizes next week.
    Context window
    The maximum combined input+output tokens a model can process in one call.
    Lost in the middle
    The observed tendency of long-context models to recall information less reliably when it sits in the middle of a long input.
    Sliding window (context)
    Keeping only the most recent N turns/tokens of a conversation.
    Rolling summarization
    Periodically compressing older conversation turns into a running summary.
    Embedding model
    A model that maps a piece of text to a vector representing its meaning.
    Cosine similarity
    A measure of the angle between two vectors, used to score how semantically similar two texts are.
