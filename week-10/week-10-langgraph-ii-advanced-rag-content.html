    LangGraph II & Advanced RAG

    Pausing a graph for human review, hybrid search, re-ranking, and wiring RAG into a graph node as one step of a larger agentic flow.

    By the end of this lesson, you will be able to

    • Pause a LangGraph run for human review with interrupt(), and resume it with Command(resume=...).
    • Explain hybrid search (vector + keyword) and why vector-only retrieval misses exact-match terms.
    • Add a re-ranking step that reorders retrieved chunks before generation.
    • Wire a full RAG pipeline into a LangGraph node, so retrieval becomes one step of an agentic flow instead of a standalone script.

    1. Human-in-the-loop with interrupt()

    Not every agent decision should be fully autonomous. When your Corte 2 project (or a real deployment) makes a consequential choice — sending an email, deleting a record, or in today's case, answering from a low-confidence retrieval — you may want a human to approve it first. LangGraph supports this natively: interrupt() pauses a node mid-execution and saves the graph's state (via the checkpointer from Week 9); your application resumes it later with the human's decision.

    python
    from langgraph.types import interrupt, Command

def review_node(state: RAGState) -> dict:
    if state["confidence"] < 0.6:
        decision = interrupt({
            "question": state["question"],
            "draft_answer": state["draft_answer"],
            "ask": "approve, edit, or reject this low-confidence answer",
        })
        return {"final_answer": decision["edited_answer"] if decision["action"] == "edit" else decision.get("text", state["draft_answer"])}
    return {"final_answer": state["draft_answer"]}

# ... elsewhere, after graph.invoke(...) returns with an interrupt pending:
result = graph.invoke({"question": "..."}, config=config)
if "__interrupt__" in result:
    print(result["__interrupt__"])                       # show the pending review to a human
    graph.invoke(Command(resume={"action": "approve"}), config=config)  # continue with their decision

    Because this relies on the same checkpointer from Week 9, the pause can last arbitrarily long — even across process restarts, if you use a persistent checkpointer instead of InMemorySaver.

    2. Hybrid search: vector + keyword

    Week 4's RAG system retrieved purely by embedding similarity. That fails for queries containing exact tokens embeddings blur together — error codes, course codes, exact function names, IDs. Hybrid search runs a keyword search (e.g. BM25, or ChromaDB's built-in full-text filtering) alongside vector search and merges the two ranked lists, so an exact match on "ADK-1039" is not drowned out by semantically-similar-but-wrong chunks.

    A simple, dependency-free merge strategy: run both searches, then combine with reciprocal rank fusion (sum 1 / (60 + rank) per chunk across both lists, re-sort by the combined score).

    3. Re-ranking

    Retrieval optimizes for recall (find plausible candidates fast); re-ranking optimizes for precision (put the best few first). A dedicated cross-encoder model scores each (query, chunk) pair jointly — more accurate than embedding similarity alone, but too slow to run over an entire corpus, so you retrieve a wider top-k first, then re-rank just those:

    python
    # Free, local re-ranking with a small cross-encoder (no paid API required)
from sentence_transformers import CrossEncoder

reranker = CrossEncoder("cross-encoder/ms-marco-MiniLM-L-6-v2")  # small, CPU-friendly

def rerank(query: str, chunks: list[str], top_k: int = 3) -> list[str]:
    scores = reranker.predict([(query, c) for c in chunks])
    ranked = sorted(zip(scores, chunks), key=lambda x: x[0], reverse=True)
    return [chunk for _, chunk in ranked[:top_k]]

    If you would rather avoid an extra local model, an LLM call ("given this question, rank these 6 passages from most to least relevant") works too — slower and costs a call, but zero extra dependencies. Use whichever fits your Corte 2 project's constraints; both are legitimate for the rubric below.

    4. RAG as a graph node

    Wiring Week 4's RAG pipeline into a LangGraph node is mostly a matter of moving it from a standalone function into a node signature, so it can sit alongside other agentic steps (tool calls, human review, other specialists):

    python
    class RAGState(TypedDict):
    question: str
    chunks: list[str]
    draft_answer: str
    confidence: float
    final_answer: str

def retrieve_node(state: RAGState) -> dict:
    vector_hits = collection.query(query_embeddings=[embed(state["question"])], n_results=8)["documents"][0]
    keyword_hits = keyword_search(state["question"], top_k=8)          # your BM25 / full-text search
    merged = reciprocal_rank_fusion(vector_hits, keyword_hits)
    return {"chunks": rerank(state["question"], merged, top_k=3)}

def generate_node(state: RAGState) -> dict:
    context = "\n\n".join(state["chunks"])
    response = llm.invoke(f"Answer using ONLY this context:\n{context}\n\nQuestion: {state['question']}")
    return {"draft_answer": response.content, "confidence": estimate_confidence(response, state["chunks"])}

    Now RAG is one replaceable step in a graph you can extend: a Week 9-style conditional edge can send low-confidence answers to the review_node from Section 1 instead of straight to the user.

    Glossary

    interrupt()
    Pauses a LangGraph node and saves state via the checkpointer, awaiting a human decision.
    Command(resume=...)
    Resumes an interrupted graph run with the human's decision.
    Hybrid search
    Combining vector similarity search with keyword/exact-match search, merged into one ranked list.
    Reciprocal rank fusion
    A simple, weight-free method for merging two ranked lists by summing 1/(k+rank) per item.
    Re-ranking
    A second, more precise scoring pass over a retrieval's top-k results, using a cross-encoder or an LLM.
