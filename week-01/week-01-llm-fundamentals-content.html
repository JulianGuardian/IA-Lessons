    1. Welcome to AI Agentic Engineering

    This course sits at the intersection of two things that used to be separate disciplines: software engineering and large language models (LLMs). Until recently, "using AI" in an application meant calling a classifier or a recommendation model that did one narrow thing. Today, a single API call can reason over free-form instructions, call tools, retrieve information, and chain multiple steps together to complete an open-ended task. That capability is what we call an agent, and building reliable, evaluable, production-grade systems around it is what we call AI (agentic) engineering.

    2. What is a Large Language Model?

    A large language model is a neural network trained to do one deceptively simple thing extremely well: predict the next token given everything that came before it. Everything an LLM appears to do — answer questions, write code, hold a conversation, call a tool — emerges from repeating that single prediction step, one token at a time, over and over (this is called autoregressive generation).

    2.1 Tokens: the model's alphabet

    LLMs don't read letters or whole words — they read tokens, sub-word chunks produced by a tokenizer (commonly a byte-pair encoding or SentencePiece algorithm). A token might be a whole common word ("the"), a fragment of a longer word ("token" + "izer"), punctuation, or even a partial byte for rare characters. As a rule of thumb for English text, 1 token ≈ 4 characters ≈ 0.75 words. This matters immediately in engineering terms: every model has a maximum number of tokens it can read and generate in one call (its context window, which we dedicate all of Week 3 to), and every provider bills per token.

    2.2 Embeddings: meaning as coordinates

    Before a token can be processed mathematically, it is converted into an embedding: a vector (a long list of numbers, typically hundreds to thousands of dimensions) that represents the token's meaning as a point in space. Tokens used in similar contexts end up with similar vectors — the embeddings for "king" and "queen" are close together, and famously, king - man + woman ≈ queen in a well-trained embedding space. We will use this same idea — measuring how "close" two pieces of text are in vector space — as the backbone of semantic search and RAG starting in Week 3.

    2.3 Attention: deciding what to look at

    The architecture that made modern LLMs possible is the Transformer (Vaswani et al., 2017, "Attention Is All You Need" — see Further Reading). Its key mechanism, self-attention, lets every token in a sequence look at every other token and decide, dynamically, how much each of them matters for understanding it. In the sentence "The trophy didn't fit in the suitcase because it was too big", attention is what lets the model correctly connect "it" to "trophy" rather than "suitcase", by weighting the trophy token heavily when building the representation for "it". Stacking many attention + feed-forward layers on top of each other, and training on massive amounts of text, is what gives an LLM its ability to model long-range structure in language.

    2.4 Putting it together: one generation step

    The model repeats this entire pipeline once per output token, each time re-reading the whole sequence so far (original prompt + everything generated). That repetition is why longer generations take longer and cost more, and why how you pick the next token from the probability distribution — the topic of the next section — has such a visible effect on the result.

    3. Inference Parameters: Controlling How the Model Chooses Words

    The last step of the pipeline above (sampling) doesn't just pick the single most likely next token every time — that would make output robotic and repetitive. Instead, the model produces a full probability distribution over its entire vocabulary, and a handful of parameters control how a token is drawn from that distribution.

    ParameterWhat it doesLow valueHigh value
    temperature Rescales the probability distribution before sampling. Divides the logits by this value. 0.0–0.3: peaked, near-deterministic, repeatable — good for extraction, classification, code. 0.8–1.2: flatter distribution, more variety and creativity, more risk of drifting off-topic.
    top_p (nucleus sampling) Restricts sampling to the smallest set of tokens whose cumulative probability ≥ p. 0.1: only the most probable tokens are ever considered. 1.0: every token with non-zero probability is eligible.
    top_k Restricts sampling to the k single most probable tokens, regardless of their probability mass. 1: equivalent to greedy decoding (always the top token). 40+: allows more unusual word choices.
    max_output_tokens Hard cap on how many tokens the model is allowed to generate in this call. Generation stops early if a stop token is produced first. Short answers, lower latency, lower cost. Room for long-form output; does not force the model to use it.

    Engineering rule of thumb

    For tasks with a single correct answer (data extraction, classification, generating JSON, function-call arguments), use low temperature (0–0.3) and let top_p/top_k sit at their defaults. For open-ended writing or brainstorming, raise temperature first before touching top_p/top_k — changing three knobs at once makes behavior hard to reason about.

    You'll run a controlled experiment sweeping these parameters against the same prompt in today's notebook — seeing the distribution collapse and widen is far more convincing than reading about it.

    4. Free-Tier Models You Can Use in This Course

    This course runs entirely on free-access APIs. You are free to experiment with any of the following, but all graded labs and projects are guaranteed to work with Gemini, which is what the instructor will demo with and what the starter notebooks target by default.

    FamilyHow to access for freeNotes
    Gemini (Google) Google AI Studio → free API key, generous free-tier request quota Primary model for this course. Fast gemini-flash-latest tier is more than enough for every exercise; native JSON-schema output, function calling, and long context windows.
    Llama (Meta, open-weight) Free inference tiers on providers such as Groq or OpenRouter, or run locally with Ollama (no API key needed at all) Good for understanding that "the model" and "the API" are separable — the same open weights are served by many different free and paid providers.
    Mistral (Mistral AI, open-weight + hosted) La Plateforme free developer tier, or self-hosted via Ollama European alternative; strong small models; useful for comparing output style and instruction-following against Gemini/Llama on the same prompt.

    Keeping your code provider-agnostic where possible (small wrapper functions, configurable model name) is good practice — you'll feel the benefit the moment you want to swap models to compare cost, latency, or quality.

    5.4 Make your first call — three ways

    All three snippets below send the exact same prompt to the exact same Gemini model. The point isn't which tool is "better" — it's recognizing the same underlying LLM call underneath every framework you'll touch this semester. We'll go deep on ADK and LangGraph starting Week 6–7; for now we're just getting comfortable with the syntax.

    Option A — raw google-genai SDK
    import os
from dotenv import load_dotenv
from google import genai

load_dotenv()
client = genai.Client(api_key=os.environ["GOOGLE_API_KEY"])

response = client.models.generate_content(
    model="gemini-flash-latest",
    contents="In one sentence, what is a large language model?",
)
print(response.text)
    Option B — Google ADK (one-line agent)
    from google.adk.agents.llm_agent import Agent

root_agent = Agent(
    model="gemini-flash-latest",
    name="intro_agent",
    instruction="Answer in exactly one sentence.",
)
# In this notebook we call the agent programmatically with the ADK Runner;
# see today's notebook for the full runnable version.
    Option C — LangChain chat model
    from langchain_google_genai import ChatGoogleGenerativeAI

llm = ChatGoogleGenerativeAI(model="gemini-flash-latest")
response = llm.invoke("In one sentence, what is a large language model?")
print(response.content)

    7. Key Takeaways & Glossary

    • An LLM is fundamentally a next-token predictor; everything else is that idea applied repeatedly.
    • Tokens, not characters or words, are the unit LLMs read, write, and are billed in.
    • Embeddings place tokens (and, as we'll see in Week 3–4, whole passages) as points in a meaning-space where distance signals semantic similarity.
    • Self-attention lets the model dynamically weigh which earlier tokens matter for the one it's currently processing.
    • temperature, top_p, and top_k shape the sampling step; they trade determinism for variety.
    • Whichever tool you call it through (raw SDK, ADK, LangChain), you are always ultimately making the same underlying API call.
    LLM (Large Language Model)
    A neural network trained to predict the next token in a sequence of text.
    Token
    A sub-word unit of text; the basic unit an LLM reads/writes and is billed on.
    Embedding
    A numeric vector representing the meaning of a token or piece of text.
    Attention
    The Transformer mechanism that weighs how much each token should influence another token's representation.
    Context window
    The maximum number of tokens (input + output) a model can handle in a single call. Deep dive in Week 3.
    Temperature
    A sampling parameter that scales the probability distribution over the next token; higher = more random.
