    Corte 2 project (due Week 11): a multi-agent system that solves a real problem, built with Google ADK or LangGraph and integrating RAG — worth 25% (project) + 5% (in-class activities) of your grade. You will build the pieces week by week starting today.

    1. What is an AI agent?

    A plain LLM call is a function: text in, text out. It cannot check today's weather, query a database, or send an email — it can only guess what those things might say, and it will hallucinate confidently if you let it. An agent wraps an LLM in a loop that lets it:

    1. Perceive — read the user's request and the current state of the world (tool results so far).
    2. Reason — decide, in natural language, what to do next.
    3. Act — call a tool (a function, an API, a database query) that actually changes or reads the world.

    The loop repeats — the result of the action becomes new perception — until the model decides it has enough information to give a final answer.

    Everything you will build for the rest of the course — a single ADK agent, a LangGraph state machine, a multi-agent swarm — is this loop, dressed up with more structure. Today you build it by hand once, so nothing a framework does later feels like magic.

    2. Tool use and function calling

    "Function calling" is a training-time capability: modern LLMs (Gemini, GPT, Llama 3+, Mistral) have been fine-tuned to recognize when a user's request needs external information or action, and to emit a structured, machine-readable request to call one of the functions you described to them — instead of answering in prose.

    The round-trip has four steps, and you (the application code) are responsible for steps 2 and 4 — the model never executes anything itself:

    Every tool you expose to an LLM needs a name, a natural-language description (the model's only way to know when to use it), and a schema for its parameters. In the raw Gemini API this looks like:

    python
    from google import genai
from google.genai import types

def get_course_topic(week: int) -> dict:
    """Look up which topic is covered in a given week of this course."""
    topics = {6: "Agent fundamentals", 7: "Google ADK", 8: "Multi-agent systems"}
    return {"week": week, "topic": topics.get(week, "unknown")}

client = genai.Client(api_key="...")
config = types.GenerateContentConfig(tools=[get_course_topic])  # google-genai can wrap a plain Python function

response = client.models.generate_content(
    model="gemini-flash-latest",
    contents="What are we covering in week 7?",
    config=config,
)
print(response.text)  # SDK auto-executes the tool and feeds the result back for you

    The google-genai SDK can auto-execute plain Python functions passed as tools (as shown above) — convenient, but it hides the round-trip. Section 4 below builds the loop manually so you see every step.

    3. Agent patterns: ReAct vs. Plan-and-Execute

    ReAct (Reasoning + Acting)

    Introduced by Yao et al., 2022, ReAct interleaves a visible Thought (why do this next), an Action (a tool call), and an Observation (the tool's result) on every iteration. The model re-plans after every single tool result — flexible, and easy to debug because you can literally read its reasoning, but it can take many small steps for a task that has an obvious upfront plan.

    Plan-and-Execute

    Here the model first writes a full multi-step plan, and only then executes each step (optionally re-planning if a step fails). Fewer expensive "thinking" calls to the LLM for tasks that are naturally sequential, but less adaptive mid-task — if step 2 reveals the plan is wrong, you need explicit re-planning logic.

    PatternBest forCost pattern
    ReActOpen-ended, exploratory tasks where the next step depends on the last result1 LLM call per step
    Plan-and-ExecuteTasks with a predictable structure (e.g. "book flight, then hotel, then rental car")1 planning call + cheaper execution calls

    Google ADK's default LlmAgent tool loop (next week) and LangGraph's create_react_agent (this week's lab) both implement ReAct. You will meet an explicit Plan-and-Execute-style workflow agent (SequentialAgent) in Week 8.

    4. Walkthrough: a ReAct loop with no framework

    Before any framework does this for you, build it yourself once. This loop calls Gemini, checks whether it asked for a function call, executes it locally, feeds the result back, and repeats — the exact PRA loop from Section 1, in about 25 lines:

    python
    from google import genai
from google.genai import types

def get_course_topic(week: int) -> dict:
    """Look up which topic is covered in a given week of this course."""
    topics = {6: "Agent fundamentals", 7: "Google ADK", 8: "Multi-agent systems", 9: "LangGraph I"}
    return {"week": week, "topic": topics.get(week, "unknown")}

TOOLS = {"get_course_topic": get_course_topic}
tool_declarations = [types.Tool(function_declarations=[
    types.FunctionDeclaration(
        name="get_course_topic",
        description="Look up which topic is covered in a given week of this course.",
        parameters={"type": "OBJECT", "properties": {"week": {"type": "INTEGER"}}, "required": ["week"]},
    )
])]

client = genai.Client(api_key="...")
contents = [types.Content(role="user", parts=[types.Part.from_text(text="What topic is week 8 about?")])]

for step in range(5):  # PRA loop, capped so a confused model cannot loop forever
    response = client.models.generate_content(
        model="gemini-flash-latest", contents=contents,
        config=types.GenerateContentConfig(tools=tool_declarations),
    )
    part = response.candidates[0].content.parts[0]
    if part.function_call:                                    # ACT: model asked for a tool
        call = part.function_call
        print(f"[Thought -> Action] calling {call.name}({dict(call.args)})")
        result = TOOLS[call.name](**call.args)                # your code executes it
        print(f"[Observation] {result}")
        contents.append(response.candidates[0].content)
        contents.append(types.Content(role="user", parts=[
            types.Part.from_function_response(name=call.name, response=result)
        ]))
        continue                                                # PERCEIVE: loop with the new observation
    print("[Final answer]", part.text)                          # model is done reasoning
    break

    Run this in a Python file or a REPL — watch it print a Thought/Action pair, an Observation, then a final answer. This is literally what every agent framework you use from now on is doing under the hood.

    ⚙️ Tooling corner (1/5): Google Antigravity CLI — scaffolding a tool function

    You now understand exactly what a "tool" needs: a typed function signature and a clear docstring. Ask Antigravity to scaffold one instead of typing boilerplate by hand:

    terminal
    agy
> Add a Python function `estimate_study_hours(topic: str, difficulty: str) -> dict` to tools.py.
  It should return {"topic":..., "difficulty":..., "hours": <int>} using a simple lookup table for
  difficulty in {"easy","medium","hard"}. Include a docstring suitable as an LLM tool description.

    Review the generated docstring carefully — it is the only thing the model reads to decide when to call your tool, so vague wording (e.g. "does stuff with topics") will cause the agent to miss or misuse it.

    Glossary

    Agent
    An LLM wrapped in a loop that lets it call tools and re-reason on their results until it reaches a goal.
    Perception-Reasoning-Action (PRA) loop
    The read-decide-act cycle underlying every agent framework.
    Tool use / function calling
    An LLM capability to emit a structured request to call an application-defined function instead of answering in prose.
    ReAct
    Agent pattern that interleaves a visible Thought, an Action (tool call), and an Observation on every step.
    Plan-and-Execute
    Agent pattern that plans all steps upfront, then executes them, optionally re-planning on failure.
    Trajectory
    The full sequence of thoughts, tool calls, and observations an agent produced for one task — what ADK's evaluation framework compares in Week 12.
